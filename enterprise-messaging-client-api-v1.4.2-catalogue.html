Messages 2 APIs

MethodEndpointCapability
POST/api/v1/messagesPublish a message
Publishes a message to a platform-configured logical destination. The platform resolves the underlying subject and persistence resources.
POST/api/v1/messages/batchPublish a batch of messages
Publishes multiple messages and returns an outcome for each entry. A single request accepts at most 500 messages. SDKs must automatically split larger application batches into sequential or bounded-concurrency chunks of no more than 500 messages, preserve per-message outcomes, and avoid retrying successful entries unless the same idempotency keys are reused.

Subscriptions 9 APIs

Create and manage application-level message delivery.

MethodEndpointCapability
POST/api/v1/subscriptionsCreate a subscription
Creates an application subscription handle. It does not expose or provision a native NATS consumer.
GET/api/v1/subscriptionsList subscriptions
Lists subscriptions visible to the authenticated application.
GET/api/v1/subscriptions/{subscriptionId}Get a subscription
Returns the current state of a subscription.
DELETE/api/v1/subscriptions/{subscriptionId}Close a subscription
Closes the application subscription handle. The platform manages underlying consumer lifecycle.
GET/api/v1/subscriptions/{subscriptionId}/messagesReceive messages
Retrieves messages from a pull-mode subscription. Messages require explicit acknowledgement. Add waitMs for bounded long polling.
GET/api/v1/subscriptions/{subscriptionId}/eventsStream message events
Opens a Server-Sent Events connection for push-mode delivery. Each message event contains a DeliveredMessage. Acknowledge using the acknowledgement endpoints. The server assigns a stable event ID to each delivered event and sends it in the SSE id field. After a disconnect, reconnect with the Last-Event-ID header set to the last completely processed event ID to resume delivery. The SDK should persist the last processed event ID only after the application has safely handled the event. If the cursor is no longer available, the server returns the documented cursor-expired error and the SDK must follow the configured recovery policy.
POST/api/v1/subscriptions/{subscriptionId}/pausePause message delivery
Pauses delivery to this logical application subscription. It does not delete the subscription or alter the underlying platform-managed consumer configuration.
POST/api/v1/subscriptions/{subscriptionId}/resumeResume message delivery
Resumes delivery to a paused logical application subscription.
GET/api/v1/subscriptions/{subscriptionId}/metricsGet subscription processing metrics
Returns application-level delivery and acknowledgement metrics. Native consumer configuration and server internals are not exposed.

Acknowledgements 4 APIs

Confirm processing, request redelivery, or handle failed deliveries.

MethodEndpointCapability
POST/api/v1/subscriptions/{subscriptionId}/messages/{messageId}/acknowledgementsAcknowledge a message
Confirms successful processing. Repeated acknowledgement of an already settled delivery is treated idempotently.
POST/api/v1/subscriptions/{subscriptionId}/messages/{messageId}/negative-acknowledgementsReject a message for redelivery
Requests redelivery according to platform retry policy. delaySeconds is advisory and subject to policy.
POST/api/v1/subscriptions/{subscriptionId}/messages/{messageId}/processing-extensionsExtend message processing time
Indicates processing is ongoing and requests an acknowledgement deadline extension, subject to platform policy.
POST/api/v1/subscriptions/{subscriptionId}/messages/{messageId}/terminationsTerminate message delivery
Marks this delivery as permanently failed. DLQ routing, if enabled, is controlled by platform policy.

MethodEndpointCapability
POST/api/v1/requestsSend a request and await a reply
Sends a request to a logical destination and waits for a correlated response. Reply routing and temporary messaging resources are managed by the platform.

Replay & Reprocessing 2 APIs

Replay retained messages or request controlled reprocessing.

MethodEndpointCapability
POST/api/v1/subscriptions/{subscriptionId}/replaysStart a message replay
Requests replay from an approved logical position. Retention, authorization and replay limits are validated by the platform; native sequence numbers are not exposed.
POST/api/v1/messages/reprocessReprocess selected messages
Requests controlled reprocessing of previously delivered messages by platform message identifiers.

Destinations 3 APIs

Discover and request registration of application destinations.

MethodEndpointCapability
POST/api/v1/destinationsRequest a new destination
Requests registration of a logical destination for the authenticated application. The platform validates naming, ownership, authorization and messaging-mode requirements. For CORE, it authorizes the logical subject for permitted operations. For JETSTREAM, it verifies that the destination can be mapped to an existing application-approved stream; if platform provisioning is required, the request is routed for approval. This operation does not create or modify NATS streams or expose native NATS administration.
GET/api/v1/destinationsList application destinations
Lists logical destinations registered for the authenticated application.
GET/api/v1/destinations/{destination}Get destination details
Returns registration status and granted application permissions for a logical destination.

Dead-Letter Handling 1 APIs

Inspect messages routed to the application's configured dead-letter destination.

MethodEndpointCapability
GET/api/v1/subscriptions/{subscriptionId}/dead-letter-messagesList dead-letter messages
Lists messages routed to the application's configured dead-letter destination after policy-defined delivery failures. This endpoint is available only when DLQ handling is enabled for the application.
